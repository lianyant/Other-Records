# git 舍弃未add的变动



当您在 Git 中进行了一些更改但尚未执行 `git add` 命令将这些变动加入暂存区时，您可以使用以下几种方法来舍弃这些未暂存的变动：

**1. 舍弃特定文件的更改**

- **使用 `git checkout` (传统方式):**
  
  Bash
  
  ```
  git checkout -- <文件名>
  ```
  
  例如，如果您修改了名为 `script.js` 的文件并且想要撤销这些更改：
  
  Bash
  
  ```
  git checkout -- script.js
  ```
  
  这条命令会将指定文件恢复到最近一次提交时的状态（或者，如果文件是新创建且未被追踪的，这条命令可能不会对其产生预期的撤销效果，而是用于切换分支等其他操作，但对于已追踪文件的修改，它会撤销更改）。`--` 符号用于分隔命令和文件名，以防止文件名被误解为分支名。

- **使用 `git restore` (Git 2.23 版本及更新版本的推荐方式):**
  
  Bash
  
  ```
  git restore <文件名>
  ```
  
  例如：
  
  Bash
  
  ```
  git restore script.js
  ```
  
  `git restore` 命令是较新的命令，专门用于恢复工作区文件。

**2. 舍弃所有未暂存的更改**

- 使用 git checkout (传统方式):
  
  要舍弃当前目录下所有已跟踪文件但未暂存的更改，可以执行：
  
  Bash
  
  ```
  git checkout -- .
  ```
  
  这个命令会撤销当前目录（包括子目录）中所有已跟踪文件的未暂存修改。请谨慎使用，因为它会丢失所有这些更改。

- 使用 git restore (Git 2.23 版本及更新版本的推荐方式):
  
  要舍弃当前目录下所有未暂存的更改，可以执行：
  
  Bash
  
  ```
  git restore .
  ```
  
  这条命令的效果与 `git checkout -- .` 类似，用于恢复当前工作目录中所有已修改的文件到它们在上次提交时的状态。

**3. 关于未追踪的文件 (Untracked files)**

上述命令主要影响的是已经被 Git 跟踪的文件的修改。如果您创建了一些新文件，这些文件在执行 `git add` 之前是未被追踪的 (untracked)。`git checkout -- .` 或 `git restore .` **不会**删除这些未追踪的新文件。

如果您也想删除这些未追踪的文件和目录，可以使用 `git clean` 命令。这是一个比较有风险的操作，因为它会永久删除文件。

- **查看将要被删除的未追踪文件 (演习模式):**
  
  Bash
  
  ```
  git clean -n
  ```
  
  或者，如果要查看将要删除的未追踪文件和目录：
  
  Bash
  
  ```
  git clean -nd
  ```

- **删除未追踪的文件:**
  
  Bash
  
  ```
  git clean -f
  ```

- **删除未追踪的文件和目录:**
  
  Bash
  
  ```
  git clean -fd
  ```
  
  使用 `git clean` 命令时务必小心，确保您了解它将删除哪些内容。

**4. 使用 `git stash` (临时保存更改)**

如果您不确定是否要完全舍弃这些更改，或者想稍后再回来处理它们，可以使用 `git stash`：

Bash

```
git stash push -u -m "临时保存未暂存的更改"
```

或者简单地：

Bash

```
git stash
```

（默认情况下，`git stash` 会保存已暂存和未暂存的更改。如果只想保存未暂存的更改和未追踪文件，可以加上 `-u` 或 `--include-untracked` 选项）。

这会将您的工作目录和暂存区的更改（包括未暂存的）保存在一个“储藏栈”中，让您的工作目录回到干净的状态（即上次提交的状态）。之后，如果您确定不需要这些更改了，可以执行 `git stash drop` 来删除最近的储藏。如果您想恢复这些更改，可以使用 `git stash pop` 或 `git stash apply`。

**总结**

- 对于**特定文件**的未暂存更改：
  - `git checkout -- <文件名>`
  - `git restore <文件名>` (推荐)
- 对于**所有文件**的未暂存更改：
  - `git checkout -- .`
  - `git restore .` (推荐)
- 对于**未追踪的文件和目录** (新添加但未 `git add` 的)：
  - `git clean -fd` (请谨慎使用)

在执行任何会删除工作的命令之前，建议先使用 `git status` 仔细检查当前状态，确保您了解将要舍弃的是哪些更改。
