在 GitHub 上推送了一个提交后，如果想撤销该提交，可以考虑以下两种方法：

### 方法 1：使用 git revert（推荐方法）

这种方法会生成一个新的提交，该提交的作用是反向操作之前的更改，保留整个提交历史。适用于公共仓库以及多人协作的情况。

**步骤：**

1. 找到你想撤销的提交的哈希值（可以用 `git log` 查看）。
2. 执行以下命令来生成一个反向提交：
   
   ```bash
   git revert <commit-hash>
   ```
   
   如果要撤销最近的一次提交，可以直接用：
   
   ```bash
   git revert HEAD
   ```
3. 按提示完成提交信息的编辑（或直接保存默认信息）。
4. 将新生成的提交推送到远程仓库：
   
   ```bash
   git push origin <branch-name>
   ```

### 方法 2：使用 git reset 并强制推送

这种方法会直接修改提交历史，将目标提交以及其后的提交全部删除（如果用 `HEAD~1` 则只删除最后一次提交）。这种方法适用于个人分支或在确认没有其他人基于该分支工作的情况下使用，因为强制推送可能会影响他人的工作。

**步骤：**

1. 使用 `git reset` 回退到某个提交，比如回退到上一个提交：
   
   ```bash
   git reset --hard HEAD~1
   ```
2. 强制推送到远程仓库：
   
   ```bash
   git push origin <branch-name> --force
   ```
   
   **注意：** 强制推送可能会覆盖其他人已经拉取的历史，务必谨慎使用！

### 总结

- **使用 git revert**：适合公共仓库，安全且不改变已有提交历史。
- **使用 git reset + 强制推送**：适合个人开发环境，但需要注意可能引发协作问题。

选择哪种方法取决于你的具体需求和仓库使用情况。
