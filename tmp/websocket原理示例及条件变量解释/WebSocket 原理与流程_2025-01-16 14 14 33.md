## 一、WebSocket 的概念

1. **基于 TCP 长连接的双向通信协议**  
   WebSocket 是一种在单个 TCP 连接上进行**全双工**（双向）通信的协议。它与传统的 HTTP 请求-响应模式不同，HTTP 基于一次请求、一次响应，通信结束就要断开连接，而 WebSocket 则可以在建立连接之后，保持一个持续的、能够同时收发数据的通道。

2. **通过 HTTP/1.1 升级（Upgrade）握手完成连接**  
   WebSocket 的握手是从 HTTP 协议升级（HTTP Upgrade 头部）过来的，这意味着初次建立 WebSocket 连接时，仍会先发起一次 HTTP 请求，通过服务器返回指定的响应头部，告诉客户端“我们可以使用 WebSocket 协议了”，然后两端再切换到 WebSocket 协议进行双向通信。

3. **减少通信开销、支持实时数据交互**  
   使用 WebSocket 后，客户端和服务器之间可以随时双向发送和接收数据，而不需要像传统轮询方式（Polling）那样频繁发送大量无用的 HTTP 请求，极大地减少通信开销，提升实时性。

4. **与其他实时通信技术对比**  
   - **轮询（Polling）**: 客户端每隔一定时间发送一次 HTTP 请求，问服务器“有新数据吗？”。如果大部分时间没有数据更新，就会浪费带宽和服务器资源。  
   - **SSE（Server-Sent Events）**: 服务器可以单向推送数据给客户端，但客户端无法主动发消息给服务器，只能通过 Ajax 等方式再另行发送。  
   - **WebSocket**: 客户端和服务器均可主动发送消息给对方，效率更高，应用更灵活。

## 二、WebSocket 的工作原理

### 1. 建立连接（握手过程）

1. **客户端发起握手请求**  
   - 用户在 Web 前端使用浏览器（或其他客户端）发起一个 HTTP 请求，但这个请求会携带特定的头部信息，表明它想要升级到 WebSocket 协议。  
   - 一般包含 `Upgrade: websocket` 和 `Connection: Upgrade` 等关键头部。  
   - 客户端还会发送一个 `Sec-WebSocket-Key` 头部，供服务器校验以完成握手。

2. **服务器接受并响应**  
   - 服务器通过检查请求头，确认是否支持升级协议，如果可以就将协议从 HTTP 升级到 WebSocket。  
   - 服务器返回包含 `Sec-WebSocket-Accept` 等头部的响应，告诉客户端已完成 WebSocket 协议的确认。  
   - 一旦握手成功，浏览器端和服务器端就不再按 HTTP 方式工作，而是开始通过 TCP 连接直接交换 WebSocket 帧。

3. **协议切换成功**  
   - 连接正式建立，后续数据传输将使用 WebSocket 的分帧机制，通过统一的 TCP 通道进行双向传输。

### 2. 数据帧与消息传输

一旦连接建立后，WebSocket 会在底层通过“帧”（frame）的方式发送和接收数据。大致分为以下几类帧：

- **文本帧（Text Frame）**：发送的内容是纯文本格式，如 JSON 字符串等。
- **二进制帧（Binary Frame）**：可以发送二进制数据，常用于文件传输、音视频流等。
- **控制帧（Control Frame）**：如关闭连接帧、ping/pong 帧等，用于连接健康检查或关闭连接等控制操作。

在应用层面，开发者往往只需要关心“发送文本消息”和“接收文本消息”，浏览器会底层帮我们处理封包、解包等操作。

### 3. 连接保持与关闭

- **保持连接**  
  WebSocket 一旦建立，就保持在一个持久化连接上。但如果空闲时间过长或网络故障、断线，可能会引发超时或连接被中断，需要客户端和服务器进行心跳检测（ping/pong）来验证连接的健康性。
- **关闭连接**  
  当客户端或服务器需要断开连接时，会向对方发送一个“关闭连接”的控制帧，对方再响应之后，双方再断开 TCP 连接。

## 三、Web 前端与服务器的交互流程

从前端的角度，使用 WebSocket 往往经过以下流程（示意概念）：

1. **创建 WebSocket 对象并指定服务器端地址**  
   - 前端代码中，会通过 `new WebSocket("ws://example.com")` 或者 `wss://example.com`（HTTPS 场景下通常使用 wss）来创建连接。  
   - 注意：在创建过程中，会发生前面所述的 HTTP -> WebSocket 的握手过程。

2. **监听与处理连接状态事件**  
   前端会关注几个核心事件，以便知道连接何时建立、何时收到消息、是否出错等等：
   - **onopen**：连接成功建立时触发  
   - **onmessage**：收到服务器消息时触发  
   - **onerror**：通信出现错误时触发  
   - **onclose**：连接关闭时触发

3. **发送消息**  
   - 一旦连接建立 (`onopen` 事件触发之后)，前端就可以使用 `WebSocket.send(...)` 将数据发送给服务器。  
   - 发送的数据可以是字符串，也可以是二进制（如 Blob、ArrayBuffer）。

4. **接收消息**  
   - 当服务器通过相同的 WebSocket 通道主动推送消息时，前端会在 `onmessage` 回调中捕捉到。  
   - 可以从事件对象里读取消息数据，然后进行相应的处理或页面更新等。

5. **关闭连接**  
   - 前端在需要时可以调用 `WebSocket.close()` 方法主动关闭连接。  
   - 如果服务器或网络原因导致关闭连接，也可以在 `onclose` 回调中获取通知。

## 四、WebSocket 的典型应用场景

1. **在线聊天/IM 即时通讯**  
   用户之间需要实时发送消息给对方，传统轮询方式很浪费网络带宽，WebSocket 可以让服务器与客户端保持持续连接，实现消息的瞬时收发与分发。

2. **实时数据推送（如股票行情、体育赛事）**  
   需要持续更新的数据，如果用轮询方式，就会频繁请求；WebSocket 则能在服务器一侧发生事件变更时立即推送给各客户端。

3. **协同编辑/多人在线协作**  
   多个用户同时编辑文档或进行在线协作时，需要实时同步各自的操作，WebSocket 的低延迟、全双工特性非常适合。

4. **在线游戏**  
   在多人在线游戏中，客户端和服务器之间需要大量实时交互，使用 WebSocket 能降低延迟并提升交互效率。

## 五、WebSocket 使用时的注意事项

1. **协议与安全**  
   - 如果站点基于 HTTPS，建议使用安全版的 WebSocket（`wss://`）；  
   - 如果是普通的 HTTP，使用 `ws://` 即可；  
   - 生产环境常常会使用反向代理服务器（如 Nginx），要保证代理服务器支持 WebSocket 转发。

2. **心跳检测**  
   - 长时间不活跃时，可能被中间网络设备（路由器、防火墙等）自动断开连接；  
   - 前端和服务端一般会实现 ping/pong 机制定时探测，确保连接正常。

3. **连接断开重连**  
   - 如果 WebSocket 断开，前端需要有重连机制（如延时重连、次数限制等）来保证用户体验；  
   - 可以在 `onclose` 或 `onerror` 回调中触发重连逻辑。

4. **消息格式和数据协议设计**  
   - 收发消息时，建议使用统一的数据格式（常见为 JSON），以便实现数据的可扩展和易解析；  
   - 如果传输二进制数据，需要考虑最大传输大小、分片处理等问题。

## 六、与 HTTP 不同之处的总结

1. **连接方式**:  
   - HTTP：一次请求，一次响应，随后连接默认断开（除非使用 HTTP/1.1 的 keep-alive，但依旧是请求-响应模式）。  
   - WebSocket：通过一次握手升级，一旦连接建立，就在单个 TCP 通道上维持双向通信。

2. **通信模式**:  
   - HTTP：客户端请求 -> 服务器响应；  
   - WebSocket：双方都可以自由地向对方发送消息，不再依赖谁先请求。

3. **实时性和效率**:  
   - HTTP：频繁轮询会带来带宽和资源浪费；  
   - WebSocket：实时、低延迟，更适合高频次、双向交互的应用场景。

4. **使用场景**:  
   - HTTP：适合静态文件、RESTful API 的一次性请求；  
   - WebSocket：在线聊天、实时推送、协同编辑等需要双向实时更新的业务。

## 七、小结

WebSocket 通过一次 HTTP 升级握手建立起一个持久的、双向的通信管道，极大提升了前端与服务器之间实时交互的效率。在前端开发中，通过监听连接状态事件、调用发送和接收方法，可以方便地实现聊天、实时数据推送以及各种在线协同功能。

如果你现在想让 Web 前端与后端保持长连接、实时双向通信，那么 WebSocket 通常是最佳选择。它的关键点就在于：

- **一次 HTTP 升级** -> **持续的 TCP 双向通道**。  
- **双向数据传输**。  
- **减少轮询开销，提高实时性**。

### main.cpp

```cpp
#include <websocketpp/config/asio_no_tls.hpp>
#include <websocketpp/server.hpp>

#include <iostream>
#include <string>
#include <functional>
#include <map>

// 声明一个 server 类型，使用 websocketpp::config::asio_no_tls
typedef websocketpp::server<websocketpp::config::asio> server;

// 方便后面使用的类型别名
using websocketpp::connection_hdl;

// 为了演示，这里简单用一个 map 维护连接和用户 ID 等信息（可按需扩展）
std::map<connection_hdl, std::string, std::owner_less<connection_hdl>> g_connection_user_map;

/**
 * @brief  连接建立时触发的回调
 */
void on_open_handler(server* s, connection_hdl hdl) {
    // 你可以在此生成一个用户ID，也可以将 hdl 转成 connection_ptr 做更多操作
    // 这里只是示例输出提示信息
    std::string user_id = "User_" + std::to_string(g_connection_user_map.size() + 1);
    g_connection_user_map[hdl] = user_id;

    std::cout << "[on_open] A new connection established: " << user_id << std::endl;
}

/**
 * @brief  连接关闭时触发的回调
 */
void on_close_handler(server* s, connection_hdl hdl) {
    if (g_connection_user_map.find(hdl) != g_connection_user_map.end()) {
        std::string user_id = g_connection_user_map[hdl];
        std::cout << "[on_close] Connection closed: " << user_id << std::endl;
        g_connection_user_map.erase(hdl);
    } else {
        std::cout << "[on_close] Unknown connection closed" << std::endl;
    }
}

/**
 * @brief  收到消息时触发的回调
 */
void on_message_handler(server* s, connection_hdl hdl, server::message_ptr msg) {
    // 示例：原样回送消息到客户端（echo）
    std::string payload = msg->get_payload();

    std::cout << "[on_message] Received: " << payload << std::endl;

    // 回发给客户端
    try {
        s->send(hdl, payload, msg->get_opcode());
    } catch (websocketpp::exception const & e) {
        std::cout << "[on_message] Error echoing message: " << e.what() << std::endl;
    }
}

/**
 * @brief  出现异常（如握手失败、连接错误等）时触发的回调
 */
void on_fail_handler(server* s, connection_hdl hdl) {
    server::connection_ptr con = s->get_con_from_hdl(hdl);
    // 输出一些错误信息
    std::cout << "[on_fail] Connection failed, reason: " 
              << con->get_ec().message() << std::endl;
}

int main() {
    try {
        // 1. 实例化server对象
        server ws_server;

        // 2. 设置日志输出等级(全部设置为none，屏蔽websocketpp自带日志)
        ws_server.clear_access_channels(websocketpp::log::alevel::all);
        ws_server.clear_error_channels(websocketpp::log::elevel::all);

        // 3. 初始化asio框架
        ws_server.init_asio();

        // 4. 设置业务处理回调函数
        // 我们在回调函数里会使用到 ws_server 本身，因此用std::bind传入
        ws_server.set_open_handler(std::bind(&on_open_handler, &ws_server, std::placeholders::_1));
        ws_server.set_close_handler(std::bind(&on_close_handler, &ws_server, std::placeholders::_1));
        ws_server.set_message_handler(std::bind(&on_message_handler, &ws_server, 
                                                std::placeholders::_1, std::placeholders::_2));
        ws_server.set_fail_handler(std::bind(&on_fail_handler, &ws_server, std::placeholders::_1));

        // 5. 设置服务器监听端口
        // 例如设置监听 9002 端口
        ws_server.listen(9002);

        // 6. 开始获取新建连接
        ws_server.start_accept();

        // 7. 启动服务器（进入事件循环）
        std::cout << "[main] WebSocket server starting at port 9002 ..." << std::endl;
        ws_server.run();

    } catch (websocketpp::exception const & e) {
        std::cerr << "[exception] " << e.what() << std::endl;
    } catch (...) {
        std::cerr << "[exception] Unknown error occurred" << std::endl;
    }

    return 0;
}
```

## 1\. 日志输出等级的区别

### 1.1 常见用法

- **`svr.set_access_channels(websocketpp::log::alevel::none);`**  
  表示将访问日志（access channels）的“启用集合”设置为 `none`，也就是说**不启用**任何访问级别的日志。

- **`ws_server_.clear_access_channels(websocketpp::log::alevel::all);`**  
  表示从当前启用的访问日志集合中，**清除**（移除）`alevel::all` 指定的所有日志级别。

如果在初始化之前，服务器的默认状态是开启了某些日志级别，那么：

- `set_access_channels(websocketpp::log::alevel::none)`  
  会**直接覆盖**成什么都不开。  
- `clear_access_channels(websocketpp::log::alevel::all)`  
  会**在原先的基础**上把所有已开启的通道都清理掉。

#### **是否效果一致？**

在大多数常见场景下，这两种写法**效果是一致的**，即都能实现“把访问日志全部禁用”的目的。  
- 如果你在程序启动时就明确要“全部关闭访问日志”，用哪种写法都可以；  
- 如果你在某些情况下只想关闭部分日志（比如只关闭 `alevel::frame_payload`），则可使用 `clear_access_channels(...)` 或 `set_access_channels(...)` 进行更细分的控制。

同理，对**错误日志（error channels）**的操作也类似。

## 2\. 提供 `set_http_handler` 的示例

`websocketpp` 除了处理 WebSocket 协议，也可处理一次简单的 HTTP 请求（比如浏览器直接 GET 端口时），我们可以设置一个 HTTP 回调函数（handler）。  
你可以在服务器初始化时，调用类似：

```cpp
ws_server_.set_http_handler(std::bind(&MyWebSocketServer::on_http, this, std::placeholders::_1));
```

然后在类里实现一个 `on_http` 方法。例如（在类 `MyWebSocketServer` 里）：

```cpp
void MyWebSocketServer::on_http(connection_hdl hdl) {
    server::connection_ptr con = ws_server_.get_con_from_hdl(hdl);

    // 你可以获取请求头、URL路径等
    std::string resource = con->get_resource();
    std::cout << "[on_http] Resource requested: " << resource << std::endl;

    // 根据需要生成响应内容
    std::string response_body = "<html><body><h1>Hello from HTTP handler!</h1></body></html>";

    con->set_body(response_body);
    con->set_status(websocketpp::http::status_code::ok);
}
```

这样当客户端使用普通的 HTTP 请求（如 `curl http://127.0.0.1:9002/`）访问时，就会进入这个回调函数，返回简单的 HTML 或者你想输出的其它内容。

## 3\. 关于“设置 URL”的示例

### 3.1 WebSocket 场景

- 在 **WebSocket** 场景里，客户端通常使用类似：  
  ```js
  new WebSocket("ws://127.0.0.1:9002/chatroom")
  ```  
  即 URL `ws://host:port/` 后面带一个路径 `/chatroom`。  
- 服务器这边并没有“server.set_url(...)” 这种接口，而是通过**获取连接**后，查看这个请求的“资源路径（resource）”或“URI”来做路由。  

在 `on_open` 或者 `on_http` 里，你可以调用：
```cpp
auto con = ws_server_.get_con_from_hdl(hdl);
std::string resource = con->get_resource(); // 例如 "/chatroom"
```
然后根据 `resource` 做不同的业务处理，比如：

```cpp
if (resource == "/chatroom") {
    // 走聊天逻辑
} else if (resource == "/broadcast") {
    // 走广播逻辑
} else {
    // 走默认逻辑 or 拒绝连接
}
```

### 3.2 HTTP 场景

- 如果是 HTTP 请求（非 WebSocket 连接），则会在 `on_http` 回调里同样获取 `con->get_resource()` 进行相应的响应处理。
- 对于 **TLS** 场景，则是 `wss://host:port/...`，逻辑相同，只是配置要改成 `asio_tls` 并设置好 SSL 上下文。

1. **日志输出等级**  
   - `set_access_channels(websocketpp::log::alevel::none)` 和  
     `clear_access_channels(websocketpp::log::alevel::all)`

```cpp
#define MY_WEBSOCKET_CLIENT_H

#include <websocketpp/config/asio_client.hpp>
#include <websocketpp/client.hpp>
#include <thread>
#include <atomic>
#include <queue>
#include <mutex>
#include <condition_variable>

class MyWebSocketClient {
public:
    MyWebSocketClient();
    ~MyWebSocketClient();

    // 初始化并连接到指定的 ws:// 或 wss:// 地址
    void connect(const std::string& uri);

    // 开始事件循环（如果不想在外面调用，也可在 connect 里直接 run）
    void run();

    // 主动发送一条消息（可供外部线程调用）
    void sendMessage(const std::string& msg);

    // 停止客户端（关闭连接）
    void stop();

private:
    // websocketpp 客户端类型（非 TLS）
    typedef websocketpp::client<websocketpp::config::asio_client> client_t;
    typedef client_t::connection_ptr connection_ptr;
    typedef websocketpp::config::asio_client::message_type::ptr message_ptr;
    typedef websocketpp::connection_hdl connection_hdl;

    void on_open(connection_hdl hdl);
    void on_message(connection_hdl hdl, message_ptr msg);
    void on_close(connection_hdl hdl);
    void on_fail(connection_hdl hdl);

    void sendingLoop(); // 循环发送线程
    void messageProcessingLoop(); // 消息消费处理线程

private:
    client_t            client_;          // websocketpp 客户端对象
    connection_hdl      conn_hdl_;        // 当前连接的 handle
    std::atomic<bool>   connected_{false};
    std::atomic<bool>   running_{true};   // 控制是否继续运行

    std::thread         process_thread_;  // 处理消息的后台线程

    std::queue<std::string> send_queue_;
    std::mutex              send_mtx_;
    std::condition_variable send_cv_;
```

```cpp
// 发送线程
void MyWebSocketClient::sendingLoop() {
    while (running_) {
        // 等待有待发送的消息 或者退出
        std::unique_lock<std::mutex> lock(send_mtx_);
        send_cv_.wait(lock, [this]{
            return !running_ || !send_queue_.empty();
        });

        while (!send_queue_.empty() && running_) {
            std::string msg = send_queue_.front();
            send_queue_.pop();

            lock.unlock(); // 解锁，避免阻塞其他线程
            if (connected_) {
                try {
                    client_.send(conn_hdl_, msg, websocketpp::frame::opcode::text);
                } catch (websocketpp::exception const & e) {
                    std::cerr << "[sendingLoop] send error: " << e.what() << std::endl;
                }
            }
            lock.lock(); // 重新加锁
        }
    }
    std::cout << "[sendingLoop] exited" << std::endl;
}

// 处理接收消息线程
void MyWebSocketClient::messageProcessingLoop() {
    while (running_) {
        std::unique_lock<std::mutex> lock(recv_mtx_);
        recv_cv_.wait(lock, [this]{
            return !running_ || !recv_queue_.empty();
        });

        while (!recv_queue_.empty() && running_) {
            std::string msg = recv_queue_.front();
            recv_queue_.pop();

            lock.unlock();
            // 在这里做耗时处理或业务逻辑
            std::cout << "[messageProcessingLoop] got message: " << msg << std::endl;
            // 如果处理很久，这里就不会阻塞其他消息的on_message回调
            // ...
            std::this_thread::sleep_for(std::chrono::milliseconds(100)); // 模拟耗时操作
            lock.lock();
        }
    }
    std::cout << "[messageProcessingLoop] exited" << std::endl;
```

## 说明与要点

1. **发送消息的线程**  
   - 在示例中，我们开启了一个 `sendingLoop()` 线程，通过一个 `std::queue<std::string>` 和 `std::mutex` / `std::condition_variable` 来管理“待发送的消息”。  
   - 外部只需要调用 `sendMessage()` 往队列里 push 消息，然后唤醒发送线程即可。  
   - 这样就可以**实现随时循环发送**或批量发送，而不会卡住 `on_open` 等回调函数。

2. **接收消息的线程**  
   - WebSocket 客户端收到数据时，会自动调用 `on_message` 回调。  
   - 如果处理很快（比如仅仅打印），可以直接在回调里处理。  
   - 如果处理**比较耗时**，或者需要队列化/排队处理，则可把消息放进 `recv_queue_`，再由一个单独的 `messageProcessingLoop()` 线程去消费处理。  
   - 这样不会阻塞 `on_message` 回调线程，减少了对底层事件循环的干扰。

3. **server 端原理相同**  
   - `websocketpp` 的 server 端也有 `on_message`, `on_open`, `on_close` 回调。  
   - 如果想要循环发送，或对消息排队处理，也可以类似地开一个线程，维护一个发送队列/接收队列。  
   - 无论客户端还是服务端，都要注意避免长时间在回调内阻塞；使用异步或线程队列往往是更好的设计。

4. **线程安全**  
   - 在多线程中操作 `websocketpp` 时，要确保对 shared 数据的访问是**线程安全**的。示例中我们使用了 `std::mutex`、`std::condition_variable`、`std::queue` 等。  
   - `websocketpp` 本身在 async 模式下，需要你自己保护共享资源（如发送队列、连接状态等）。

5. **简化**  
   - 如果你只想定时发一些消息，也可以在**`on_open`** 里开一个简单的线程，`while(running_){ send(...); std::this_thread::sleep_for(...); }`。  
   - 如果你不需要对接收的消息做排队或耗时处理，也可以不写 `recv_queue_` 那部分，直接在 `on_message` 打印或处理即可。

---

## 小结

- **循环发送**：可在**独立线程**里做 `while(...) { send(...) }`，或通过**队列**方式让主线程/其他线程投递消息。  
- **接收消息**：`on_message` 回调被自动调用；如果处理耗时，放入队列再用单独线程处理。  
- **服务端也一样**：只不过它在 `on_open`、`on_message` 里面对的是多个连接（connection_hdl），可以为每个连接维护各自的队列和线程，或者用一个更通用的调度中心。  

这样，你的 C++ WebSocket 客户端（或服务端）就能在**不中断事件循环**的情况下，进行循环发送和异步接收处理。祝开发顺利!

```cpp
void MyWebSocketClient::sendingLoop() {
    while (running_) {
        // 等待有待发送消息 或 退出
        std::unique_lock<std::mutex> lock(send_mtx_);

            send_queue_.pop();

                } catch (websocketpp::exception const & e) {
                    std::cerr << "[sendingLoop] send error: " << e.what() << std::endl;
                }
            }
            lock.lock(); // 重新加锁
        }
    }
    std::cout << "[sendingLoop] exited" << std::endl;
}

// 消息处理线程
void MyWebSocketClient::messageProcessingLoop() {
    while (running_) {
        std::unique_lock<std::mutex> lock(recv_mtx_);
        recv_cv_.wait(lock, [this]{
            return !running_ || !recv_queue_.empty();
        });

        while (!recv_queue_.empty() && running_) {
            std::string msg = recv_queue_.front();
            recv_queue_.pop();

            lock.unlock();
            // 在这里可做耗时业务逻辑
            std::cout << "[messageProcessingLoop] got message: " << msg << std::endl;
            // ...例如解析JSON、处理、再发回...
            std::this_thread::sleep_for(std::chrono::milliseconds(100));
            lock.lock();
        }
    }
    std::cout << "[messageProcessingLoop] exited" << std::endl;
}
```

```cpp
#ifndef MY_WEBSOCKET_SERVER_H
#define MY_WEBSOCKET_SERVER_H

#include <websocketpp/config/asio_no_tls.hpp>
#include <websocketpp/server.hpp>

#include <map>
#include <string>

#include <condition_variable>

#include <atomic>

// 为了区分，这里定义一个类型别名
typedef websocketpp::server<websocketpp::config::asio> server;
typedef websocketpp::connection_hdl connection_hdl;

// 每个连接的上下文（含发送/接收队列、线程等）
struct ConnectionContext {
    // 与该连接相关的 URL 路径（如 /chatroom, /someapi 等）
    std::string resource;

    // 用于发送消息的队列、线程、同步对象
    std::queue<std::string> sendQueue;
    std::mutex sendMtx;
    std::condition_variable sendCv;
    std::thread sendThread;

    // 用于接收消息后再进行处理的队列、线程、同步对象
    std::queue<std::string> recvQueue;
    std::mutex recvMtx;
    std::condition_variable recvCv;
    std::thread recvThread;

    // 标志位，用于控制线程退出
    std::atomic<bool> running{true};
};

class MyWebSocketServer {
public:
    MyWebSocketServer();
    ~MyWebSocketServer();

    // 初始化并监听指定端口
    void init(unsigned short port);

    // 运行服务器（事件循环）
    void run();

private:
    // 回调函数
    void on_open(connection_hdl hdl);
    void on_message(connection_hdl hdl, server::message_ptr msg);
    void on_close(connection_hdl hdl);
    void on_fail(connection_hdl hdl);
    void on_http(connection_hdl hdl); // 如果需要处理普通HTTP请求

    // 针对某个连接，启动发送消息的线程
    void startSendThread(connection_hdl hdl, std::shared_ptr<ConnectionContext> ctx);

    // 针对某个连接，启动处理接收消息的线程
    void startRecvThread(connection_hdl hdl, std::shared_ptr<ConnectionContext> ctx);

    // 停止并回收某个连接的线程
    void stopConnectionThreads(std::shared_ptr<ConnectionContext> ctx);

private:
    server ws_server_;

    // 存放每个连接的上下文 { connection_hdl -> context }
    // 注意：connection_hdl 不可直接作为 key，需要 owner_less<connection_hdl>
    std::map<connection_hdl, std::shared_ptr<ConnectionContext>, std::owner_less<connection_hdl>> connections_;
```

## 3. MyWebSocketServer.cpp

```cpp
#include "MyWebSocketServer.h"
#include <iostream>
#include <functional>

MyWebSocketServer::MyWebSocketServer() {
    // 构造时先不做任何事
}

MyWebSocketServer::~MyWebSocketServer() {
    // 在服务器退出时，如果还有连接也需要停止它们的线程
    for (auto &pair : connections_) {
        stopConnectionThreads(pair.second);
    }
    connections_.clear();
}

void MyWebSocketServer::init(unsigned short port) {
    // 1. 屏蔽 websocketpp 的自带日志
    ws_server_.clear_access_channels(websocketpp::log::alevel::all);
    ws_server_.clear_error_channels(websocketpp::log::elevel::all);

    // 2. 初始化 Asio
    ws_server_.init_asio();

    // 3. 设置回调
    ws_server_.set_open_handler(std::bind(&MyWebSocketServer::on_open, this, std::placeholders::_1));
    ws_server_.set_message_handler(std::bind(&MyWebSocketServer::on_message, this,
                                             std::placeholders::_1, std::placeholders::_2));
    ws_server_.set_close_handler(std::bind(&MyWebSocketServer::on_close, this, std::placeholders::_1));
    ws_server_.set_fail_handler(std::bind(&MyWebSocketServer::on_fail, this, std::placeholders::_1));
    // 如果需要处理普通 HTTP 请求，可设置
    ws_server_.set_http_handler(std::bind(&MyWebSocketServer::on_http, this, std::placeholders::_1));

    // 4. 监听端口
    ws_server_.listen(port);

    // 5. 开始接受连接
    ws_server_.start_accept();
}

void MyWebSocketServer::run() {
    // 进入事件循环
    ws_server_.run();
}

// 连接建立
void MyWebSocketServer::on_open(connection_hdl hdl) {
    // 获取连接指针
    auto con = ws_server_.get_con_from_hdl(hdl);
    // 获取请求路径（resource）
    std::string resource = con->get_resource(); // e.g. "/chatroom"

    // 创建一个连接上下文
    auto ctx = std::make_shared<ConnectionContext>();
    ctx->resource = resource;

    {
        // 放入 map
        connections_[hdl] = ctx;
    }

    // 针对这个连接启动发送线程 & 接收处理线程
    startSendThread(hdl, ctx);
    startRecvThread(hdl, ctx);

    std::cout << "[on_open] New connection. Resource: " << resource << std::endl;
}

// 收到消息
void MyWebSocketServer::on_message(connection_hdl hdl, server::message_ptr msg) {
    auto it = connections_.find(hdl);
    if (it == connections_.end()) {
        // 未知连接
        return;
    }
    auto ctx = it->second;

    // 将消息放入当前连接的 recvQueue
    {
        std::lock_guard<std::mutex> lock(ctx->recvMtx);
        ctx->recvQueue.push(msg->get_payload());
    }
    ctx->recvCv.notify_one();
}

// 连接关闭
void MyWebSocketServer::on_close(connection_hdl hdl) {
    auto it = connections_.find(hdl);
    if (it != connections_.end()) {
        // 停止并回收线程
        stopConnectionThreads(it->second);
        connections_.erase(it);
    }
    std::cout << "[on_close] Connection closed" << std::endl;
}

// 连接失败
void MyWebSocketServer::on_fail(connection_hdl hdl) {
    // 说明连接建立过程中或运行中出现异常
    auto con = ws_server_.get_con_from_hdl(hdl);
    std::cerr << "[on_fail] Connection failed, reason: "
              << con->get_ec().message() << std::endl;

    // 这里也做类似清理
    auto it = connections_.find(hdl);
    if (it != connections_.end()) {
        stopConnectionThreads(it->second);
        connections_.erase(it);
    }
}

// 如果要支持普通 HTTP 请求（非 WebSocket）
void MyWebSocketServer::on_http(connection_hdl hdl) {
    auto con = ws_server_.get_con_from_hdl(hdl);
    // 简单返回一个响应
    con->set_body("<html><body><h1>Hello from HTTP!</h1></body></html>");
    con->set_status(websocketpp::http::status_code::ok);
}

// 启动发送线程：循环从 sendQueue 取数据，send给客户端
void MyWebSocketServer::startSendThread(connection_hdl hdl, std::shared_ptr<ConnectionContext> ctx) {
    ctx->sendThread = std::thread([this, hdl, ctx](){
        while (ctx->running) {
            std::unique_lock<std::mutex> lock(ctx->sendMtx);
            // 等待有消息 或者 线程结束
            ctx->sendCv.wait(lock, [ctx] {
                return !ctx->running || !ctx->sendQueue.empty();
            });

            while (!ctx->sendQueue.empty() && ctx->running) {
                std::string msg = ctx->sendQueue.front();
                ctx->sendQueue.pop();
                lock.unlock();

                // 发送到客户端
                try {
                    ws_server_.send(hdl, msg, websocketpp::frame::opcode::text);
                } catch (websocketpp::exception const & e) {
                    std::cerr << "[sendThread] send error: " << e.what() << std::endl;
                }

                lock.lock();
            }
        }
        std::cout << "[sendThread] Exited for resource=" << ctx->resource << std::endl;
    });
}

// 启动接收线程：循环从 recvQueue 取消息，做耗时处理或再发给客户端
void MyWebSocketServer::startRecvThread(connection_hdl hdl, std::shared_ptr<ConnectionContext> ctx) {
    ctx->recvThread = std::thread([this, hdl, ctx](){
        while (ctx->running) {
            std::unique_lock<std::mutex> lock(ctx->recvMtx);
            ctx->recvCv.wait(lock, [ctx] {
                return !ctx->running || !ctx->recvQueue.empty();
            });

            while (!ctx->recvQueue.empty() && ctx->running) {
                std::string msg = ctx->recvQueue.front();
                ctx->recvQueue.pop();
                lock.unlock();

                // 在这里做业务处理，比如：
                std::cout << "[recvThread] Resource=" << ctx->resource
                          << " Received: " << msg << std::endl;

                // 根据 resource 做不同的逻辑
                if (ctx->resource == "/chatroom") {
                    // 演示：回发给客户端
                    {
                        std::lock_guard<std::mutex> sLock(ctx->sendMtx);
                        ctx->sendQueue.push("[echo from chatroom] " + msg);
                    }
                    ctx->sendCv.notify_one();
                } else if (ctx->resource == "/game") {
                    // ... 处理 "/game" 连接的消息
                } else {
                    // 其他路径
                }

                lock.lock();
            }
        }
        std::cout << "[recvThread] Exited for resource=" << ctx->resource << std::endl;
    });
}

// 停止并回收线程
void MyWebSocketServer::stopConnectionThreads(std::shared_ptr<ConnectionContext> ctx) {
    ctx->running = false;
    // 通知两个队列
    ctx->sendCv.notify_all();
    ctx->recvCv.notify_all();

    if (ctx->sendThread.joinable()) {
        ctx->sendThread.join();
    }
    if (ctx->recvThread.joinable()) {
        ctx->recvThread.join();
    }
}
```

# 代码说明

1. **ConnectionContext 结构**  
   - 维护了**两个线程**：`sendThread` 和 `recvThread`。  
   - 维护了**两个队列**：`sendQueue` 和 `recvQueue`。  
   - 用 `std::atomic<bool> running{true};` 控制线程循环结束。  

2. **on_open**  
   - 当有新连接时，创建一个 `ConnectionContext`，根据其 `resource`（URL 路径）做记录。  
   - 将它存入 `connections_` 映射表，并调用 `startSendThread()` 和 `startRecvThread()` 启动对应的后台线程。

3. **on_message**  
   - 将收到的消息 push 到 `recvQueue` 里，再 `notify_one()` 唤醒 `recvThread` 来做耗时处理或业务逻辑。  
   - 如果不需要耗时处理，你也可以直接在 `on_message` 回调里处理，然后发送。这里只是演示“排队处理”。

4. **发送线程** (`startSendThread`)  
   - 等待 `sendQueue` 里出现数据（或者 `running` 变为 false）。  
   - 有数据就 `ws_server_.send(...)` 发给客户端。  
   - 这样就不会阻塞在主线程或回调线程里。

5. **接收线程** (`startRecvThread`)  
   - 等待 `recvQueue` 出现数据（或者 `running` 变 false）。  
   - 取出后做业务逻辑，比如根据 `ctx->resource` 判断是 `/chatroom` 还是 `/game`，再决定如何处理，也可广播给其他连接等。  
   - 在示例里，简单地做了“echo 回发”的操作演示。

6. **on_close / on_fail**  
   - 连接关闭或失败时，调用 `stopConnectionThreads(...)` 来把该连接的线程都安全停止并 join，最后从 `connections_` 中移除。

7. **HTTP 请求**  
   - 如果普通浏览器用 `http://127.0.0.1:9002/` 访问，而不是 `ws://`，就会进入 `on_http` 回调，在这里可以返回一个简单的 HTML 或 JSON。
   - 如果你不需要 HTTP，去掉 `ws_server_.set_http_handler(...)` 即可。

8. **URL 区分**  
   - 在 `on_open` 里 `con->get_resource()` 取得客户端请求的路径，比如 `ws://127.0.0.1:9002/chatroom` 就会得到 `/chatroom`。  
   - 你可以根据 `resource` 作出不同的业务处理，比如**单独分配**某些队列或存储到不同的映射结构里等。  
   - 在示例中，我们只是把它存在 `ConnectionContext::resource`，后续可在发送/接收线程里使用。
