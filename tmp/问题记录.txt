在 C++ 中，`enum class` 和传统的 `enum` 虽然都用于定义枚举类型，但它们之间有几个关键的区别，使得 `enum class`（也被称为 "scoped enums" 或 "strongly typed enums"）在很多情况下更受推荐。下面是这两种枚举类型的主要区别：

### 1. **作用域（Scoping）**
- **`enum class`**：引入了自己的作用域。枚举成员必须通过枚举类型名访问，例如 `AgvState::Init`。这避免了名称冲突和全局命名空间的污染。
- **`enum`**：没有自己的作用域。枚举成员直接在包含它们的作用域中可见，这可能导致名称冲突。

### 2. **类型安全（Type Safety）**
- **`enum class`**：提供更强的类型安全。`enum class` 类型的变量不能直接赋值给其他类型的变量（如 `int`），除非显式进行类型转换。这减少了错误和意外行为的风险。
- **`enum`**：较弱的类型安全。传统枚举的值可以直接赋给整数类型的变量，也可以与整数直接比较，这可能导致依赖于具体值的脆弱代码。

### 3. **隐式转换（Implicit Conversions）**
- **`enum class`**：不支持隐式类型转换。要将 `enum class` 的值转换为其他类型，需要使用显式的类型转换，如 `static_cast<int>(AgvState::Init)`。
- **`enum`**：支持隐式转换到整数类型，这使得它们可以不经修改地用于数学运算和比较。

### 4. **基础类型（Underlying Type）**
- **`enum class`**：可以显式指定基础类型。例如，`enum class AgvState : uint8_t { ... };` 这允许开发者控制存储枚举值所用的内存大小。
- **`enum`**：虽然 C++11 也允许为传统的 `enum` 指定基础类型，但在早期的 C++ 标准中，基础类型通常由编译器自动选择。

### 示例对比
```cpp
enum class AgvState {
    Init,       // 必须通过 AgvState::Init 访问
    Waiting,
    Doing
};

enum AgvState {
    Init,       // 直接通过 Init 访问
    Waiting,
    Doing
};

AgvState state;
state = Init; // 如果是 enum，这是合法的。
state = AgvState::Init; // 如果是 enum class，这是必需的。
```

### 总结
`enum class` 由于其增强的作用域规则和类型安全特性，通常是更好的选择。它通过减少全局作用域污染和提供更强的类型检查，
帮助避免错误和提高代码质量。当需要与 C 代码接口或需要枚举值直接作为整数使用时，传统的 `enum` 也可能是合适的选择。

要清空数据库表中的所有内容，你有两个常用的 SQL 命令可选择：

1. **`DELETE FROM`**：
   使用 `DELETE FROM` 命令可以删除表中的所有记录，但不删除表本身，也不影响表的结构、索引、约束等设置。
   ```sql
   DELETE FROM table_name;
   ```
   这个命令将删除指定表（`table_name`）中的所有行。如果想限制只删除符合特定条件的行，可以添加 `WHERE` 子句，但在这种情况下我们不使用 `WHERE` 子句，以便删除所有记录。

2. **`TRUNCATE TABLE`**：
   `TRUNCATE TABLE` 命令用于快速清空表中的所有数据，这通常比 `DELETE FROM` 更快，因为它不扫描每一行数据，直接删除数据页。此外，`TRUNCATE` 通常会重置任何自增主键的计数器。
   ```sql
   TRUNCATE TABLE table_name;
   ```
   这个命令删除表中的所有数据并重置表的大小，通常用于完全清空一个表。

### 选择哪个命令？
- 如果你需要一个快速且不关心事务日志的方式来清空表（比如在测试环境中重置表），`TRUNCATE TABLE` 是一个好选择。
- 如果你的表涉及到复杂的触发器或你需要保留事务日志以便进行回滚，那么 `DELETE FROM` 是更合适的选择。

在执行这些操作时，请确保你有足够的权限，并且对正在操作的数据非常清楚，以避免意外的数据丢失。

问：
为什么父类指针指向子类对象时，父类指针明明代表的就是子类对象了，但是除了子类重写了父类的虚函数之外的内容，调用到的都是父类中的内容而不是子类中的内容呢?
答：
在 C++ 中，父类指针指向子类对象时，调用的成员函数依赖于函数是否为虚函数，这是由 C++ 的静态类型和动态类型的区别以及多态的实现方式决定的。这里有几个关键概念需要理解：

### 静态类型与动态类型
- **静态类型**是变量声明时的类型，编译器在编译时就确定了它。
- **动态类型**是变量指向的对象的实际类型，只有在运行时才能确定。

当你用父类指针指向子类对象时，该指针的静态类型是父类，而其动态类型是子类。

### 多态与虚函数
- **多态**允许我们通过父类的指针或引用来调用实际子类对象的方法。多态的实现依赖于虚函数。
- **虚函数**使得子类可以重写父类的行为。如果一个函数在基类中被声明为虚函数，那么在任何派生类中对该函数的重写都将参与运行时的动态绑定，即通过基类的指针或引用调用该函数时，实际调用的是对象的动态类型对应的函数实现。

### 非虚函数的调用
- 对于非虚函数，不存在动态绑定。调用哪个版本的函数完全取决于指针或引用的静态类型。因此，即使父类指针指向了一个子类对象，通过这个父类指针调用非虚函数时，依然调用的是父类中定义的版本。

### 设计原因
- **性能考虑**：不是所有的函数都需要动态绑定。虚函数的调用比普通函数调用具有更高的开销（需要通过虚表来间接调用），所以只有那些设计为可能需要在子类中改变行为的函数才应声明为虚函数。
- **明确行为**：使得对象的行为更加明确，避免意外重写，非虚函数的行为总是可以预测的，它遵循的是其静态类型的定义。

因此，除非函数被声明为虚函数，否则通过基类指针调用的总是基类中定义的函数，这保证了代码的稳定性和预测性，同时也有助于优化性能。这种设计使得开发者可以明确控制哪些行为是可以被子类修改的，哪些是固定不变的。

了解内部原理，我们可以更深入地探讨 C++ 的对象模型和如何在编译时和运行时处理方法调用。以下是 C++ 中非虚函数和虚函数调用的内部机制：

### 非虚函数调用机制
非虚函数的调用在编译时就已经确定了。当编译器看到通过一个父类指针调用一个函数时，它会根据指针的**静态类型**（编译时类型）决定调用哪个函数。这种调用不需要在运行时解析，因为它不依赖于指针所指向的对象的具体类型，而是直接关联到了指针的类型。因此，这种调用是直接的，没有额外的运行时开销。

例如，当你通过父类指针调用一个非虚函数时，编译器生成的代码将直接跳到该函数在父类中的地址。这意味着无论指针实际指向的是父类类型还是派生自该父类的子类对象，被调用的函数代码都是父类中定义的那一份。

### 虚函数调用机制（动态绑定）
当函数被声明为虚函数后，C++ 使用一种称为**虚函数表**（通常称为 vtable）的机制来支持运行时多态。每个类有一个虚函数表，其中包含指向类的虚函数实现的指针。每个对象都会包含一个指向其类虚表的指针（称为 vptr）。

当通过父类指针调用虚函数时，发生的是：
1. 查找该对象的 vptr（这个指针是在对象的内存布局的开始位置）。
2. 使用 vptr 访问虚表。
3. 从虚表中找到对应虚函数的入口。
4. 调用虚表中的函数地址，这通常指向子类中重写的函数实现，如果子类提供了重写的话。

这种机制允许在运行时根据对象的动态类型调用正确的函数实现，从而实现多态。这也是为什么通过基类指针能够调用到子类重写的虚函数的原因。

### 为什么需要这样的机制？
C++ 的设计目标之一是为了提供对象的抽象能力，同时又不损失性能。对于那些不需要多态的场景，使用非虚函数可以避免虚函数带来的性能开销。对于需要多态的场景，虚函数提供了灵活性和扩展性，但这种灵活性是以稍微增加的运行时开销为代价的（需要额外的内存和间接调用）。

总结来说，C++ 中的函数调用机制提供了一种平衡性能和功能的方法，使得开发者可以根据具体需要选择最适合的策略。

在C++中，当子类没有重写父类的虚函数时，子类对象的虚函数表（vtable）会复制父类的虚函数地址。这是因为虚函数表的设计是为了支持多态性，即运行时根据对象的实际类型来决定调用哪个方法。

这里是详细的解释：

1. **继承和虚函数表（vtable）**：当子类继承父类时，如果子类没有提供某个虚函数的新实现（即没有重写这个虚函数），那么子类的虚函数表会自动继承父类虚函数表中对应的函数地址。这就意味着，子类对象中对应的虚函数表项仍然指向父类中的虚函数实现。

2. **对象实例化**：当创建一个子类对象时，该对象内存中的虚函数表指针（vptr）会指向这个子类的虚函数表。如果子类没有重写父类的某个虚函数，那么子类的虚函数表中对应那个虚函数的入口点依然是父类的函数实现。

3. **调用过程**：当通过父类的指针或引用调用这个虚函数时，运行时系统会通过对象的虚函数表指针找到虚函数表，从虚函数表中获取对应函数的地址。如果这个虚函数在子类中没有被重写，那么虚函数表中的地址仍然是父类的实现，因此调用的就是父类的虚函数。

这种设计允许子类继承父类的行为，而无需重新定义所有父类的方法，同时仍然提供了重写（override）的机会，以实现多态性和定制化行为。

总结来说，如果子类没有重写父类的虚函数，子类对象的虚函数表中该虚函数的地址会自动指向父类的实现，这保证了继承的连续性和一致性。当然，如果子类提供了新的实现，子类的虚函数表则会更新为新的函数地址，从而实现多态行为。

继续提问：
这种情况类似于 子类继承父类时针对子类的普通成员函数重载父类的普通成员函数的情况？

在C++中，虚函数的重写（override）和普通成员函数的重载（overload）是两种不同的概念，它们在继承中起着不同的作用：

1. **虚函数的重写（Override）**：
   - **目的**：虚函数重写的目的是在子类中提供一个与父类虚函数相同签名（即相同的函数名、参数列表和返回类型）的新实现，以实现多态行为。
   - **行为**：当通过父类的指针或引用调用一个虚函数时，将会根据对象的实际类型（动态类型）来决定调用哪个实现，即运行时会查找对象的虚函数表并调用相应的函数。
   - **条件**：只有声明为`virtual`的函数才能被重写。

2. **普通成员函数的重载（Overload）**：
   - **目的**：重载允许在同一作用域内存在多个同名函数，但它们的参数类型或数量不同。在继承中，子类可以定义一个与父类同名但参数列表不同的普通成员函数，这被视为新的函数，而不是重写或替换。
   - **行为**：如果子类中的函数与父类的函数同名但参数不同，这时发生的是重载，而不是重写。调用哪个函数取决于调用时使用的参数类型和数量（静态类型），而与对象的实际类型无关。
   - **静态绑定**：普通成员函数的调用是静态绑定的，即编译时就已经确定了调用哪个函数，基于调用代码中使用的类型。

在你的问题中，如果子类没有重写父类的虚函数，子类对象中虚函数表的对应项仍然指向父类的函数实现。这与普通成员函数的重载情况不同，因为重载不影响多态性或虚函数表，而是创建了新的、独立的函数实体。

总结一下，虚函数的重写是多态性的核心，允许运行时根据对象的实际类型调用适当的方法，而普通成员函数的重载则是静态绑定，主要用于提供同一函数名的不同实现，适用于不同的调用情况。

继续提问：
讲一下子类继承父类的成员函数时，子类中的继承自父类的成员函数仍然是属于父类的吗？
当子类继承父类时，子类会继承父类的成员函数，这些函数在子类中的行为有以下几个特点：

1. **成员函数的继承**：
   - 子类继承父类的成员函数，意味着除非在子类中显式地提供了这些函数的新实现（重写或重载），否则子类对象可以直接调用继承自父类的成员函数。

2. **函数的归属**：
   - 从技术的角度看，继承自父类的成员函数在逻辑上是属于父类的，因为这些函数的定义是在父类中完成的。但从使用的角度来看，这些函数成为了子类对象的一部分，子类的实例可以直接调用这些继承来的函数，就如同这些函数是在子类中定义的一样。

3. **重写与隐藏**：
   - 如果子类重写了父类的虚函数（即在子类中提供了一个与父类虚函数完全相同签名的函数），那么通过子类的对象调用该函数时，将调用子类的实现，实现多态。
   - 如果子类中声明了一个与父类非虚函数同名的函数（但可能签名不同），这通常称为函数隐藏。在这种情况下，子类的函数并不是重写父类的函数，而是隐藏了同名的父类函数。这意味着如果通过子类的对象调用该函数，将使用子类的定义；如果需要调用父类的版本，则必须显式指定。

4. **作用域和可见性**：
   - 子类可以通过`::`运算符明确调用父类的成员函数，例如`父类名::函数名()`，这可以用来调用被子类隐藏的父类函数或在子类方法中调用父类的实现。

总的来说，虽然继承自父类的成员函数在定义上属于父类，但它们在子类中的存在使得子类对象可以将这些函数视为自己的一部分，可以自由调用这些函数。同时，这些函数的行为（是否多态、是否隐藏等）取决于它们在父类中的声明方式（是否为`virtual`）以及子类是否提供了新的实现或声明。

问：
当你定义一个类具有虚函数（特别是当类作为接口使用时），通常需要提供一个虚析构函数。
这是为了确保当通过基类指针删除派生类对象时，派生类的析构函数能够被正确调用，从而避免资源泄漏
这句话，我的理解是这样的，你看看对不对：
当一个类含有虚析构函数时，当这个类的指针指向该类的子类对象时，能够保证子类的析构函数也可以被调用到
(前提是子类的析构函数也是虚函数时)。对吧？
答：
你的理解基本上是正确的，但有一点小的调整需要注意：子类的析构函数会被调用，不论它是否被显式地声明为虚函数。在 C++ 中，如果基类的析构函数是虚的，那么所有派生类的析构函数自动也是虚的，即使你没有显式地在子类中标记它为虚。

### 关键点说明

当基类有一个虚析构函数时，这就保证了无论通过基类指针还是引用来删除派生类对象时，都会正确地调用到派生类的析构函数。这是因为析构函数的调用会遵循从派生类到基类的顺序。这个过程被称为析构函数的“自上而下”的调用机制。

#### 举例说明
假设你有一个基类 `Base` 和一个派生自 `Base` 的类 `Derived`。`Base` 类有一个虚析构函数。

```cpp
class Base {
public:
    virtual ~Base() {
        std::cout << "Destructing Base\n";
    }
};

class Derived : public Base {
public:
    ~Derived() override { // 这里的 override 是可选的，因为基类析构函数是虚的
        std::cout << "Destructing Derived\n";
    }
};
```

现在，如果你通过一个基类的指针来删除一个派生类的对象：

```cpp
Base* b = new Derived();
delete b;  // 正确地调用 Derived 的析构函数，然后是 Base 的析构函数
```

输出将会是：
```
Destructing Derived
Destructing Base
```

这个行为确保了当你通过基类指针删除对象时，派生类的资源也会被正确释放，从而避免资源泄漏。

### 总结
所以，你的理解是正确的，只需记住即便不显式声明子类析构函数为虚，它们也是虚的（如果基类析构函数是虚的）。这种设计是 C++ 保护多态类对象资源正确释放的方式之一。

18.
子类public继承父类，父类的构造函数是private权限的，这样继承下来后子类的构造函数的权限设置为public(无论是否设置为public？) 
都会造成子类的构造函数的实现报错？

答案：
当子类通过 `public` 继承自父类时，如果父类的构造函数是 `private` 的，那么子类确实无法直接调用这些私有的构造函数来初始化其父类部分。
这种情况会导致编译错误，因为子类需要能够访问并调用其父类的至少一个构造函数来正确地构造其父类部分。

### 情景分析

1. **父类构造函数为私有 (`private`)**: 这意味着只有父类自身的成员函数或友元函数可以调用这些构造函数。子类不是父类的友元（除非明确声明），
因此子类不能调用这些私有构造函数。

2. **子类的构造函数尝试调用父类构造函数**: 在 `C++` 中，每个子类构造函数会（在执行自己的体内代码前）尝试调用其父类的一个构造函数，
通常是默认构造函数（如果没有在子类构造函数的初始化列表中显式指定其他的父类构造函数）。如果父类只有私有的构造函数，子类就无法完成这一过程，
从而导致编译错误。

3. **设置为 `public` 无效**: 即使子类的构造函数被设置为 `public`，这并不影响它对父类私有成员（包括构造函数）的访问权限。
`public` 关键字控制的是其他代码对子类构造函数的可访问性，而不改变子类对父类内部私有成员的访问权限。

### 解决方案

要解决这个问题，有几种可能的方法：

- **修改父类构造函数的访问权限**：将父类中的一个或多个构造函数的访问权限改为 `protected` 或 `public`。
`protected` 允许子类访问这些构造函数，同时不允许非子类的其他代码访问。
  
- **使用友元类**：如果出于某种设计原因需要保持父类构造函数的私有性，可以将子类声明为父类的友元。
这样，子类就可以访问父类的私有构造函数。例如：

  ```cpp
  class Parent {
  private:
      Parent() { }
      friend class Child;
  };

  class Child : public Parent {
  public:
      Child() : Parent() { }  // Now legal, because Child is a friend of Parent
  };
  ```

- **使用工厂模式**：在某些设计中，可以使用工厂模式来控制对象的创建，工厂类或函数可以是父类的友元，并负责创建父类和子类的实例。

这些解决方案能够根据具体的设计需求和限制来灵活选择，以适应不同的应用场景。

19.c++的结构体中的成员函数定义也默认是内联的吗？
在 C++ 中，如果在结构体（或类）定义内部直接定义成员函数，这些函数默认是内联的。这包括构造函数、析构函数和其他成员函数。当你在类定义中直接定义成员函数时，编译器会将其视为内联函数。这意味着编译器可能会将函数调用替换为函数代码本身，以减少函数调用的开销，从而可能提高性能，尤其是对于那些被频繁调用的小函数。

然而，函数是否真正被内联取决于编译器的决定；编译器使用自己的启发式算法来决定内联一个函数是否真的能带来性能提升。这种行为可能根据编译器设置、启用的优化、函数的复杂性以及函数的调用频率而有所不同。

对于较大的函数或那些未在类体中定义的函数（即在单独的 `.cpp` 文件中定义的函数），你可以通过使用 `inline` 关键字来显式建议内联：

```cpp
struct MyClass {
    void inlineFunction() const; // 隐式内联，因为它是在类体内定义的。
    void nonInlineFunction(); // 不是内联的，因为它只在这里声明。
};

inline void MyClass::nonInlineFunction() {
    // 显式内联，因为使用了 'inline' 关键字，即使定义在类体外。
}
```

这允许更好地控制编译器行为，不过如前所述，最终决定内联与否还是由编译器来做。

21.mysql数据库相关操作：
(1).mysql清理一个mysql表的全部内容但是不删除此表的指令是什么
要清理 MySQL 表中的全部内容而不删除表本身，你可以使用 `TRUNCATE TABLE` 命令。这个命令会删除表中的所有数据，并且重置任何自增的计数器（AUTO_INCREMENT）到其初始值，但会保留表结构和其定义的索引、约束等。使用方法如下：

```sql
TRUNCATE TABLE table_name;
```

替换 `table_name` 为你想要清理的表的名称。

### 示例
假设你有一个名为 `users` 的表，想要删除其中的所有记录，可以执行：

```sql
TRUNCATE TABLE users;
```

### 注意事项
- **速度**：`TRUNCATE TABLE` 通常比删除所有行的 `DELETE FROM` 命令要快，因为它不逐行删除数据，而是通过删除并重新创建表来清空数据。
- **事务**：`TRUNCATE TABLE` 在大多数情况下是不能被回滚的。一旦执行，数据就会被永久删除。
- **权限**：执行 `TRUNCATE TABLE` 需要对表有 `DROP` 权限，因为这个操作涉及到删除表的数据部分并重新创建。
- **触发器**：`TRUNCATE TABLE` 不会触发 DELETE 触发器，因为它不是逐行删除数据。

如果因为权限或其他原因不能使用 `TRUNCATE TABLE`，你也可以使用 `DELETE FROM` 命令来删除所有行：

```sql
DELETE FROM table_name;
```

这会删除表中的所有数据，但不会重置 AUTO_INCREMENT 的值，也会触发相关的 DELETE 触发器。如果需要重置 AUTO_INCREMENT 计数器，可以单独执行：

```sql
ALTER TABLE table_name AUTO_INCREMENT = 1;
```

选择哪种方法取决于你的具体需求和上下文环境。

(2).mysql导出某个数据库的指令是什么？
在 MySQL 中，导出某个数据库通常使用 `mysqldump` 工具。这是一个命令行程序，用于创建数据库或数据库中表的 SQL dump（包括数据和结构）。使用 `mysqldump` 可以将整个数据库导出到一个 SQL 文件中，这个文件后续可以用来恢复数据库。

### 基本命令格式

```bash
mysqldump -u username -p database_name > output_file.sql
```

- **username**：你的 MySQL 用户名。
- **database_name**：你想要导出的数据库名。
- **output_file.sql**：导出的数据将保存到这个文件。

在执行此命令时，系统会提示你输入密码。如果你想避免每次都手动输入密码，可以在命令中直接包含密码（但出于安全考虑，这通常不推荐）：

```bash
mysqldump -u username -p'your_password' database_name > output_file.sql
```

确保密码紧跟在 `-p` 后面没有任何空格。

### 附加选项

- **--databases**：这个选项可以在 dump 文件中包含 `CREATE DATABASE` 语句，这样在恢复时就不需要手动创建数据库。
  
  ```bash
  mysqldump -u username -p --databases database_name > output_file.sql
  ```

- **--no-data**：这个选项允许你只导出数据库结构，不包含数据。

  ```bash
  mysqldump -u username -p --no-data database_name > structure_only.sql
  ```

- **--single-transaction**：对于使用事务存储引擎（如 InnoDB）的数据库，此选项保证了导出过程中的数据一致性，而不会阻塞其他数据库操作。

  ```bash
  mysqldump -u username -p --single-transaction database_name > output_file.sql
  ```

- **--quick**：此选项对于导出大型数据库很有用，它将数据一行行地传输到客户端而不是一次读取整个表到内存中。

  ```bash
  mysqldump -u username -p --quick database_name > output_file.sql
  ```

### 使用例子

假设你有一个名为 `mydatabase` 的数据库，用户名为 `root`，要将其导出到 `mydatabase_backup.sql` 文件：

```bash
mysqldump -u root -p mydatabase > mydatabase_backup.sql
```

这将创建一个包含 `mydatabase` 所有数据和结构的 SQL 文件。使用这个文件，你可以通过 MySQL 命令行或其他工具将数据库恢复到任何 MySQL 服务器。

(3).导入mysql数据库的指令呢？以及是否需要删除这些与导入数据库同名的已有数据库呢？
导入 MySQL 数据库的常用方法是通过 `mysql` 命令行工具使用 SQL 文件。这个 SQL 文件通常是通过 `mysqldump` 或其他数据库管理工具生成的，包含了创建数据库、表结构以及数据插入语句。

### 导入命令格式

```bash
mysql -u username -p database_name < input_file.sql
```

- **username**：你的 MySQL 用户名。
- **database_name**：你想要导入数据的目标数据库名。
- **input_file.sql**：包含数据和/或结构的 SQL 文件。

在执行此命令时，系统会提示你输入密码。

### 是否需要删除同名的已有数据库？

1. **如果 SQL 文件中包含创建数据库的语句**（如 `CREATE DATABASE`）并且你希望从头开始创建新的数据库实例，你应该先删除现有的同名数据库，然后再执行导入。这样可以避免创建数据库时出现错误，如“数据库已存在”。

   删除数据库的命令是：
   ```bash
   DROP DATABASE IF EXISTS database_name;
   ```

   然后，你可以运行导入命令。

2. **如果 SQL 文件不包含创建数据库的语句**，或者你希望将数据导入到已存在的数据库中（并且不介意覆盖或添加到现有数据），那么就不需要删除数据库。如果文件中的表与现有表重名，并且包含 `CREATE TABLE` 语句，你可能需要先删除或修改这些表，或者调整 SQL 文件中的语句以防止冲突。

### 完整的导入示例

假设你有一个名为 `mydatabase` 的数据库，用户名为 `root`，并且你有一个 `mydatabase_backup.sql` 文件，你可以这样导入数据：

1. 如果需要重建数据库：
   ```bash
   mysql -u root -p -e "DROP DATABASE IF EXISTS mydatabase; CREATE DATABASE mydatabase;"
   mysql -u root -p mydatabase < mydatabase_backup.sql
   ```

2. 如果不需要重建数据库，只需导入数据：
   ```bash
   mysql -u root -p mydatabase < mydatabase_backup.sql
   ```

这些步骤确保了你可以根据自己的需求灵活地导入数据，无论是在全新的环境中重建数据库还是在现有数据库中更新数据。

28.git的使用疑问，当我这边本地有未提交的改动，但是想要切换到另一个分支。会如何?
在使用 Git 时，如果你有未提交的改动（无论是已经暂存的还是未暂存的），然后尝试切换到另一个分支，Git 默认会阻止这种切换以保护你的修改。这是因为切换分支可能会影响当前工作目录和暂存区的内容，如果有未提交的更改，这些更改可能会与新分支上的文件产生冲突。

### 行为分析

1. **阻止切换**：
   - 如果尝试切换到另一个分支，Git 会检查你的工作目录和暂存区是否有未提交的更改。如果有，Git 会显示一个错误消息，提示存在未提交的更改，这些更改在切换分支后可能会丢失。

2. **如何处理**：
   - 有几种方法可以处理这种情况：

#### 方法一：提交更改
最直接的方法是提交你的更改。这意味着你需要先添加更改到暂存区，然后进行提交：

```bash
git add .
git commit -m "Commit message describing the changes"
```
提交后，你可以自由地切换到另一个分支。

#### 方法二：暂存更改（Stash）
如果你不想立即提交更改，因为它们还不完整或者需要保留当前工作状态，可以使用 `git stash` 命令临时保存更改：

```bash
git stash
```
这会将你的工作目录和暂存区的更改保存到一个临时的地方（stash），并恢复到你上次提交的状态。之后，你可以切换到另一个分支：

```bash
git checkout other-branch
```
在新分支上工作完成后，你可以回到原来的分支，并使用 `git stash pop` 恢复之前保存的更改：

```bash
git checkout original-branch
git stash pop
```

#### 方法三：强制切换
如果确定要切换分支，并且不介意丢失未暂存的更改（**慎用**），可以使用 `git checkout` 命令加上 `-f` 或 `--force` 选项强制切换：

```bash
git checkout -f other-branch
```
这将丢弃所有未提交的更改。

### 结论
在处理未提交的更改时尝试切换分支，Git 提供了多种保护和管理这些更改的方法。根据你的具体需求，你可以选择提交更改、
使用 stash 保存更改或者强制切换分支。每种方法都有其适用场景，重要的是选择最适合当前工作流的方法。

在 Git 中，如果你在切换分支之前有未提交的改动，并且希望暂时保存这些改动，可以使用 **git stash** 来将它们储藏起来。这样，你可以切换到其他分支，而不会丢失这些改动，等到需要时再恢复。

### 储藏改动：
1. **储藏当前的改动**：
   使用 `git stash` 命令将当前工作区和暂存区的改动储藏起来。

   ```bash
   git stash
   ```

   这会将当前未提交的修改（包括工作区和暂存区的改动）保存到 Git 的存储区中，并将工作区恢复到上一次提交的状态。

   如果你只想储藏工作区的改动（不包括暂存区的改动），可以使用：

   ```bash
   git stash -k   # 或 git stash --keep-index
   ```

   如果你只想储藏暂存区的改动（不包括工作区的改动），可以使用：

   ```bash
   git stash -p   # 或 git stash --patch
   ```

2. **查看储藏的改动**：
   如果你有多个储藏记录，可以使用 `git stash list` 来查看所有的储藏记录。

   ```bash
   git stash list
   ```

   输出类似于：

   ```
   stash@{0}: WIP on main: 1234567 Commit message
   stash@{1}: WIP on new-branch: 2345678 Another commit message
   ```

   每个储藏记录都会有一个索引（例如：`stash@{0}`、`stash@{1}`），你可以通过索引来访问它们。

### 切换分支：
你可以切换到另一个分支，而不必担心丢失未提交的改动。储藏的改动会与当前的分支无关，直到你恢复它们。

```bash
git checkout other-branch
```

### 恢复储藏的改动：
1. **恢复最新储藏的改动**：
   使用 `git stash apply` 恢复最近的储藏（不会删除储藏记录）。

   ```bash
   git stash apply
   ```

2. **恢复指定的储藏记录**：
   如果你有多个储藏记录，可以使用 `git stash apply` 指定恢复某个储藏记录，例如恢复 `stash@{1}`：

   ```bash
   git stash apply stash@{1}
   ```

3. **删除储藏记录**：
   如果你恢复了储藏并且不再需要该记录，可以使用 `git stash drop` 删除特定的储藏记录：

   ```bash
   git stash drop stash@{0}
   ```

4. **恢复并删除储藏记录**：
   使用 `git stash pop` 恢复最新的储藏，并删除该储藏记录。

   ```bash
   git stash pop
   ```

   `git stash pop` 不仅会恢复储藏的改动，还会将该储藏记录从储藏列表中删除。

### 总结：
- **git stash** 用于暂时保存未提交的改动。
- **git stash apply** 用于恢复储藏的改动，但不删除储藏记录。
- **git stash pop** 用于恢复储藏的改动并删除储藏记录。
- **git stash list** 用于查看所有储藏的记录。

#### 小端序 (Little-endian)：
在小端序中，**低字节**存储在**低地址**，**高字节**存储在**高地址**。

### 重新分析 `01 00 02 00 03 00 04 00`

假设这是一个字节序列，存储在内存中，并且我们按照 16 位整数来分组：

- 数据 2: `02 00`
- 数据 3: `03 00`

  - 低字节 `00` 存储在高地址

  - 低字节 `00` 存储在低地址
  - 高字节 `03` 存储在高地址
